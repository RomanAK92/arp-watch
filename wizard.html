ARP Watch / Guided setup

Set up your monitoring

Dashboard

1. Choose your local network

Use a Linux interface connected to the same local network as the devices you want to monitor. Routed reachability does not provide ARP visibility.

The wizard suggests the selected interface's network. The subnet must fit inside it.

Trusted devices are checked each cycle. Subnet discovery checks two additional addresses per cycle, up to 4094 hosts. A full sweep can take many minutes or hours on a large subnet. One unfamiliar MAC alone is not considered a rogue device. Current switch tracing is limited to VLAN 1.

2. Add trusted devices

Add stable IP addresses such as your router or servers. Confirm each MAC from the actual device's settings. Do not automatically trust a device just because it answered a probe.

Each row: device name · IP address · approved MACs (comma-separated).

If subnet discovery is enabled, trusted devices are optional. Silence on a trusted IP is reported as unavailable; silent unused discovery addresses do not make the sensor unavailable.

3. Optional tracing and notifications

Detection works without managed switches. Unmanaged home switches cannot report their device ports.

Each switch: name · management IP · family · transport · username · password. Blank passwords retain existing secrets.

Connections between switches

Each row: upstream switch IP · upstream port · downstream switch IP · downstream port. Add a link in each direction when needed. Skip this for a single switch.

Uptime Kuma is optional and is not installed or bundled by ARP Watch. Create a Push monitor there, interval 120 seconds, retries 0, reminders 15, then enable its Telegram profile if desired.

4. Review and start

No switch configuration, routes, VLAN memberships, or port states will be changed. Monitoring sends ARP queries on the selected interface. Existing incidents and evidence remain stored.
Required to apply setup. Switch passwords and Kuma tokens are stored privately and are never returned by the wizard.
